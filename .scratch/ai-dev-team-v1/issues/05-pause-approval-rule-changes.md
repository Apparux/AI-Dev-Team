# 05: 暂停、动作审批与规则变更确认

Milestone: M2 — 持久化与恢复
Status: ready-for-agent

**What to build:** 用户能够暂停一条研发流程、批准或拒绝具体动作，并在共享规则变化后选择如何继续；主管按持久记录执行这些决定，不把等待、规则更新或原生工具权限误当作批准。

**Blocked by:** 04 — 一个真实小 Bug 的完整交付。

**Execution gate:** 等待 M1 人工复盘及用户对后续批次的明确授权。04 完成不会自动解除本关口；未获授权不得领取。之后仅按用户指定的 `/implement` 或 `/implement-spec` 范围推进。

## 上下文与范围

对应 [TASKS T05 前半](../../../TASKS.md)，覆盖 [PRD A07 部分、A10](../../../PRD.md)；遵循 [DESIGN 第 2.3、5 节](../../../DESIGN.md)。沿用最小状态机制，不增加通用权限拦截平台。

## Acceptance criteria

- [ ] 完成“用户暂停 → 持久记录 → 停止新派发/新危险动作 → 对账后继续”的流程；在途执行可见，不声称进程已被冻结。
- [ ] 审批明确动作、范围、所属执行及相关版本；待批或拒绝时不执行受影响动作及下游，批准不跨范围、重派或不明副作用复用。
- [ ] 审批等待允许无关安全工作继续，但显式暂停/取消优先；被拒绝动作不会在恢复或改换 Harness 后重新获得默认许可。
- [ ] 相关规则指纹变化阻塞受影响的新派发及完成验收；记录差异、在途执行和用户决定，必要复验后才接续，不静默热更新。
- [ ] Harness 权限模式和业务批准分别记录；即使采用 DESIGN 第 2.4 节的最高原生权限新会话默认，也不扩大业务批准。无法可靠限制的高风险动作交给用户，不以权限模式或配置覆盖绕过约束。
- [ ] 用无破坏性的具体动作演练批准和拒绝，并验证一条规则变更流程；结果可从状态和实际行为核对，不只查看文字说明。

## 验证与执行约束

只用获准的可丢弃资源测试门禁，不用生产操作或真实破坏性命令充当测试。只覆盖本票状态转移与已知冲突；取消停止确认和完整中断恢复由 06 完成。
