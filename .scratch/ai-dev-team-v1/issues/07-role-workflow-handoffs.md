# 07: 按需岗位与文件化交接

Milestone: M3 — 研发质量闭环
Status: ready-for-agent

**What to build:** 主管能够依据任务类型选择必要岗位，通过精简的需求/设计成果、任务卡和版本化交接，让不同会话继续完成普通功能，而不依赖上一位 Agent 的私有聊天或强制完整团队到场。

**Blocked by:** 06 — 中断后安全接续与取消确认。

**Execution gate:** 必须已通过 M1 人工关口，且本票属于用户明确授权的后续批次；不得因依赖解除自动扩大实施范围。

## 上下文与范围

对应 [TASKS T06 前半](../../../TASKS.md)，验收 [PRD A04](../../../PRD.md)；遵循 PRD 岗位/工作流和 [DESIGN 第 3 节](../../../DESIGN.md) 的 Task/阶段语义。

按需要补充 Product、Architect、Backend、Frontend、QA、Reviewer 的职责和方法，支持四类轻量工作流。先以普通功能证明正常交接；完整缺陷修复循环由 08 负责，独立 Review 未实现时高风险路径只能阻塞，不能跳过。

## Acceptance criteria

- [ ] 普通功能可按需经历需求/必要设计成果 → 开发 → 验证；交接仅凭相关文件、验收条件与代码即可继续，不复制整段聊天历史。
- [ ] 小任务不强制所有岗位参与，跨端任务先明确接口/Owner；仅声明必要职责，不创建常驻岗位池或通用流程引擎。
- [ ] 不同 Task 默认新会话；同一 Task 的 QA 从已上报成果进入，不以该 Task 已 completed 为启动前提。
- [ ] 跨 Task 依赖仅消费上游已完成的明确版本；上游成果变化时阻塞受影响的下游推进并重新检查，拒绝不存在的依赖和循环。
- [ ] 各阶段具有可识别的执行者、输入/输出与验收责任；员工不能修改其他执行结果或自行完成全局任务。
- [ ] 普通功能的实际交接与一个必要门禁阻塞有证据；高风险或约定需要 Review 的任务不能在本票中绕过该门禁完成。

## 验证与执行约束

复用现有项目规范和最小任务模板，不把每次岗位派工都建成独立交付 Task。不为了展示全流程生成冗长 PRD 或无价值文档；只检验本票新增的交接和阶段行为。
