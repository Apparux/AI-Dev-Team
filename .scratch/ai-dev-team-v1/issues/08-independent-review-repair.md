# 08: 独立 Review 与有限修复闭环

Milestone: M3 — 研发质量闭环
Status: ready-for-agent

**What to build:** 对实际交付发现的正确性缺陷，系统能阻塞完成、交回开发修复、重新验证并由必要的独立 Reviewer 关闭问题；修复超限时停下来让用户决定，不无限投入或自行放宽验收。

**Blocked by:** 07 — 按需岗位与文件化交接。

**Execution gate:** 必须已通过 M1 人工关口，且本票属于用户明确授权的后续批次；前置验收通过不等于许可自动运行。

## 上下文与范围

对应 [TASKS T06 后半与 M3 出口](../../../TASKS.md)，验收 [PRD A05](../../../PRD.md)；质量门禁和轮次定义以 [DESIGN 第 7 节](../../../DESIGN.md) 为准。

严重度用于优先级，不替代正确性门禁；风格和未恶化的范围外旧问题不应扩大任务。高风险 Review 与实现者分离，可以使用同种 Harness/模型，不要求全组合。

## Acceptance criteria

- [ ] 用实际可复现的范围内缺陷跑通“发现 → 阻塞 → 开发修复 → 受影响复验 → 必要独立复核关闭”，证据绑定受检成果版本。
- [ ] 违反验收条件、新增的已确认错误/回归和实际安全等缺陷阻塞；风格/可选优化不阻塞，关键验证缺失或 INCONCLUSIVE 不能记为 PASS。
- [ ] Finding 有稳定身份、定位、证据、严重度、阻塞理由和修复/复核状态；有阻塞 finding 时主管不能完成 Task。
- [ ] 高风险 Reviewer 与实现者使用分离会话/执行者，不只是开发者自评；QA/Reviewer 不直接修改受检业务代码来掩盖问题。
- [ ] 每次修复派工有新 Attempt；同 Task 可接续开发会话，但默认两轮预算不因换 Agent、Harness、Attempt 或新增 finding 重置。
- [ ] 超限或关键验收无法完成时暂停整个 Run 的新派发，保留在途成果并请求用户决定；不能悄悄删除失败验收项。

## 验证与执行约束

用一个真实缺陷闭环及必要的轮次/证据拒绝案例证明行为。优先现有检查和受影响路径，不机械 TDD、大规模单测、全量矩阵或自动豁免。最终集成版本的证据规则由 09 补齐。
