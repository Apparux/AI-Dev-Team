# 09: Run 内逐项集成与最终版本验收

Milestone: M4 — 并行、集成与跨项目复用
Status: ready-for-agent

**What to build:** 多个已验收 Task 的成果由已有开发 Owner 在本 Run 内逐项整合，并以最终代码版本重新判断交付质量；用户得到可核验的独立分支，而不是多个分支 PASS 的拼接报告。

**Blocked by:** 08 — 独立 Review 与有限修复闭环。

**Execution gate:** 必须已通过 M1 人工关口，且本票属于用户明确授权的后续批次；不得自动推送、合并共享分支或扩大 Git 授权。

## 上下文与范围

对应 [TASKS T07](../../../TASKS.md)，验收 [PRD A09](../../../PRD.md)；遵循 [DESIGN 第 6、8 节](../../../DESIGN.md)。这是 M4 的串行集成前置，先证明整合和最终验收正确，再由 10 引入并行。

## Acceptance criteria

- [ ] 主管从已有开发岗位指定集成 Owner，在 Run 的独立集成工作区逐项消费已验收的明确 commit；不新设集成岗位，不让主管承担业务修复。
- [ ] 多 Task 的 Run 有明确最终集成交付单元；单 Task 可直接在自身最终版本验收，不为形式创建空任务。
- [ ] 集成前检查基准、实际差异、未提交状态和原写入者；冲突、越界或用户改动出现时暂停并保留现场，不覆盖、强推或自动删除工作区。
- [ ] 在最终集成版本执行必要检查，并对集成风险/受影响路径做必要 Review；不以各分支分别 PASS 推断最终 PASS。
- [ ] 后续改动使受影响的旧证据失效，重验对应路径；仍适用的证据可引用，不机械重跑全部测试或 Review。
- [ ] 报告准确列出本 Run 分支、基准/最终版本、验证状态及人工事项；没有未交代变更或后台写入，不宣称已合入主分支或兼容其他 Run。

## 验证与执行约束

用串行完成的成果验证一次成功整合和一个冲突/旧证据失效场景。只使用已获准的本地 Git 操作；跨 Run 合并、推送和发布不在本票范围。
