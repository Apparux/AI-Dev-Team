# 10: 同项目多 Run 与 Run 内并行隔离

Milestone: M4 — 并行、集成与跨项目复用
Status: ready-for-agent

**What to build:** 用户在同一仓库同时推进多个独立 Run，并在某个 Run 内并行处理真正独立的任务；写入、结果、控制和必要测试资源不互相污染，成果仍分别在各自分支验收交付。

**Blocked by:** 09 — Run 内逐项集成与最终版本验收。

**Execution gate:** 必须已通过 M1 人工关口，且本票属于用户明确授权的后续批次；实际并发场景、模型用量与测试资源需在获准范围内。

## 上下文与范围

对应 [TASKS T08](../../../TASKS.md)，验收 [PRD A08](../../../PRD.md)；工作区、资源和单主管规则以 [DESIGN 第 3、6 节](../../../DESIGN.md) 为准。

多 Run 不等于跨 Run 自动整合，也不要求通用资源调度器。默认串行；仅在接口、Owner、依赖及隔离条件明确时启用并行。

## Acceptance criteria

- [ ] 同仓库两个 Run 可同时存在，其中一个 Run 的两路独立写入实际并行；每 Run 独立配置、状态、结果、审批、工作区和交付分支。
- [ ] 一个 Run 单主管、一个工作区单写入者；未知旧执行不被新执行替代，路径别名或仓库不同入口不导致工作区误共享。
- [ ] 共享接口、Schema、公共依赖或重叠文件先明确 Owner/顺序，无法确认独立时回退串行而不是强行并行。
- [ ] 按测试项目真实需要隔离端口、临时目录或测试数据；命令实际使用对应 Run 的资源，不把 worktree 当作服务隔离。
- [ ] 资源无法隔离时只阻塞相关操作，请用户安排独占执行，其他独立工作可以继续；不自建共享资源排队器。
- [ ] 一个 Run 的暂停、修复超限或取消不误停另一个；各自沿用已验证的 Run 内集成与最终版本门禁，不自动跨 Run 合并。

## 验证与执行约束

用能够覆盖上述行为的最小并发场景，不建立全部角色/模型矩阵。用户原工作区不改动，不清理其他 Run 的资源；必要场景未获授权时保留阻塞，不用生产服务演练。
