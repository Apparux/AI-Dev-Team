# 11: 双向主管与第二技术栈复用

Milestone: M4 — 并行、集成与跨项目复用
Status: ready-for-agent

**What to build:** 用户在两个不同技术栈项目复用同一套研发资产，并能互换 Claude Code/Codex 的主管与员工用途，完成真实业务交付，而不是仅证明两个 CLI 都能启动。

**Blocked by:** 10 — 同项目多 Run 与 Run 内并行隔离。

**Execution gate:** 必须已通过 M1 人工关口，且本票属于用户明确授权的后续批次；两个验收仓库、任务和必要的本地操作由用户指定/授权。

## 上下文与范围

对应 [TASKS T09](../../../TASKS.md)，验收 [PRD A01、A02](../../../PRD.md)；执行与共享资产以 [DESIGN](../../../DESIGN.md) 为准。

已有工具级 Skill 加载、Pane 查询和父会话派发证据不是本票的完整验收。只覆盖 Claude Code 和 Codex，不顺手增加其他 Harness 或模型组合。

## Acceptance criteria

- [ ] Claude Code 主管 → Codex 员工、Codex 主管 → Claude Code 员工两个方向均完成实际任务派发、结构化交接、验证与独立分支报告。
- [ ] Harness 互换仅改变执行配置和实际原生参数，不改岗位内容、Task/Result 协议或工作流；未静默丢失必需 Skill/权限约束。
- [ ] 第二个不同技术栈 Git 项目仅登记自身配置差异，不复制核心提示词，不为接入修改业务代码；执行真实任务产生的授权业务改动允许存在。
- [ ] 同源 Skill 发现和必需支持文件访问有效；不同项目的命令、限制及资源由各自配置提供，不在共享角色中写死项目细节。
- [ ] 复用仍有效的故障/质量证据，只补环境相关风险；实际项目结果与未验证事项可定位，不把工具冒烟当作完整交付。
- [ ] 新会话遵循 DESIGN 第 2.4 节；最高原生权限不等于员工业务写入授权，每种实际执行配置与角色/任务操作仍符合本次允许范围。历史只读 profile 和一次性 YOLO 证据不构成当前业务批准。

## 验证与执行约束

两个方向各选最小有代表性的业务任务，可复用早期项目作为第一个项目。不在第二项目机械重跑全部中断、并发和模型矩阵；共享规则修改需按已实现的指纹对账流程处理。
