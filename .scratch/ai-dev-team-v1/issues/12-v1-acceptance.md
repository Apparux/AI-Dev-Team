# 12: V1 用户路径验收收口

Milestone: M4 — 并行、集成与跨项目复用
Status: ready-for-agent

**What to build:** 用户得到针对 V1 承诺的可核验验收报告，能够看清哪些用户路径已通过、哪些失败或未验证；系统不会因为票据已写完、Agent 自报成功或部分工具可用而宣布 V1 完成。

**Blocked by:** 11 — 双向主管与第二技术栈复用。

**Execution gate:** 必须已通过 M1 人工关口，且本票属于用户明确授权的后续批次；验收收口不包含自动发布、推送或超范围修复授权。

## 上下文与范围

对应 [TASKS T10](../../../TASKS.md)，逐项收口 [PRD A01–A10](../../../PRD.md)，核对 [DESIGN](../../../DESIGN.md) 与实际行为。前三份文件仍是唯一正式规格，工单和运行证据不成为新的完整规格副本。

## Acceptance criteria

- [ ] A01–A10 每项都有对应的实际版本、场景、检查结果和证据定位；明确区分官方描述、源码/静态检查、工具冒烟和完整业务验收。
- [ ] 复用有效证据，只补缺失或失效的必要场景；有必需门禁 FAIL/UNVERIFIED 时不得宣布 V1 验收完成。
- [ ] 检查权限、状态/审批、迟到结果、接管、质量闭环、并发隔离和最终版本交付之间没有未闭合的阻塞矛盾。
- [ ] 只修复范围内真正阻塞项；需要新能力、放宽权限或改变承诺时交给用户，不借验收建设新框架、增加支持范围或豁免正确性问题。
- [ ] 输出 PASS/FAIL/UNVERIFIED、证据位置和遗留事项报告，原三份文档同步实际范围；不把未经验证的恢复或原生能力写成已支持。
- [ ] 报告明确独立分支交付边界、尚需人工的操作及未来使用授权；不声称已自动跨 Run 合并、推送或发布。

## 验证与执行约束

不为收口运行无关全量套件或机械测试矩阵。保留必要验收证据，仅按项目规则清理本次临时验证资源，不自动删除有成果的分支、worktree 或用户文件。
